# Таргет `sentry` — ошибки

Только чтение, только `GET`. Sentry у нас **self-hosted**, поэтому продуктовых
надстроек вроде Seer нет — есть обычный REST API.

`DefaultJQ` оставляет от списка issues только то, что нужно для триажа:
`id`, `title`, `culprit`, `count`, `userCount`, `firstSeen`, `lastSeen`. Нужны другие
поля — передайте свой `jq`.

**На этом таргете включена редакция PII.** Пока — в режиме `warn`: тело не
меняется, а список правил, которые сработали бы (email, телефоны, карты, токены, IP),
приезжает в поле `redacted`. Набор правил выбирается по этим срабатываниям;
после переключения в `mask` совпадения заменяются на `[masked:<rule>]`, в том числе
в не-JSON ответах и в тексте ошибок upstream. Адрес — исключение: у него остаётся
домен, `ivan@acme.com` приезжает как `i***@acme.com`, потому что домен говорит, чей
это клиент, и скрывать его нечего. Стектрейс, `culprit`, тип исключения и
timestamp-ы не трогаются — расследование остаётся возможным.

**`environment` ставит сервер.** Инстанс может быть общим для контуров, поэтому
профиль прибивает `environment` к своему (`Query` в каталоге): передавать его не
нужно, а чужое значение будет заменено. Issues, релизы и события приходят только по этому
окружению — если ошибки «нет», проверьте, что смотрите в тот контур.

## Разрешённые пути

| Путь | Зачем |
|---|---|
| `/api/0/organizations/` | организации, доступные токену; у токена интеграции список пуст, слаг берите из `/api/0/organizations/<org>/projects/` |
| `/api/0/organizations/<org>/issues/` | список issues, основной вход |
| `/api/0/organizations/<org>/projects/` | какие проекты вообще есть |
| `/api/0/organizations/<org>/releases/` | релизы и их даты |
| `/api/0/issues/<id>/` | одна issue целиком |
| `/api/0/issues/<id>/events/latest/` | последнее событие: стектрейс, теги, контекст |
| `/api/0/projects/<org>/<project>/issues/` | issues одного проекта |

## Примеры

```
/api/0/organizations/<org>/issues/?query=is:unresolved&statsPeriod=24h&limit=10
/api/0/issues/48213/events/latest/
/api/0/organizations/<org>/releases/?per_page=5
```

Слаг организации `<org>` записан в описании профиля.

## Грабли

- **`release` у нас — короткий git-SHA** (7–8 hex). Это и есть связка с кодом: по нему
  ищется коммит, по коммиту — задача.
- **`statsPeriod` и `start`/`end` взаимоисключающи.** Передали оба — 400.
- **`query` — это поисковый синтаксис Sentry, а не текст.** `is:unresolved`,
  `firstSeen:-24h`, `release:abc1234`. Свободный текст ищет по заголовку.
- **`count` — за выбранный период**, а не за всё время. Сравнивать вчера с сегодня по
  нему нельзя, не выровняв период.
- **Новая issue ≠ новая ошибка.** Смотрите `firstSeen`: если он внутри периода — это
  регрессия и первый кандидат на разбор; если нет — фон.
